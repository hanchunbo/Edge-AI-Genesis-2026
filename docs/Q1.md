## 第一阶段：现代 C++20 核心内存与性能优化 (W1-W5)

### W1：内存安全、RAII 机制与智能指针 ✅

**学习目的**  
AI 推理程序常驻运行，内存泄漏是 OOM 崩溃的元凶。掌握 RAII 是从"写逻辑"到"写系统"的转变。

**核心范围**
- 智能指针（`unique_ptr` / `shared_ptr` / `weak_ptr`）底层原理
- 所有权转移逻辑与生命周期管理
- 析构函数闭环与异常安全
- `weak_ptr` 解决循环引用问题

**实战作业**  
编写 `SafeTensorBuffer` 类管理模拟显存/内存块：
- 构造函数分配资源
- 禁用拷贝构造（`= delete`）
- 支持移动语义
- 在抛出异常时验证资源 100% 自动回收

**成功指标**
- `Valgrind` 检测报告显示 "0 bytes leaked"
- 能准确说出 `shared_ptr` 引用计数原子操作对高频推理的性能损耗

**产出物**: `01_Linux_CPP_Foundations/w1_memory_safety/safe_tensor_buffer.hpp`

### W2：零拷贝思想：移动语义与右值引用 ✅

**学习目的**  
在边缘端（如 3060 或 VPS）处理 4K/8K 图像时，内存拷贝是巨大的性能浪费。

**核心范围**
- 右值引用 (`T&&`) 本质理解
- `std::move` 的实现原理
- 移动构造函数与移动赋值运算符编写
- 完美转发 `std::forward`

**实战作业**  
编写性能 Benchmark 脚本，对比将 1000 帧 4K 图像（`CustomImage` 类）存入 `std::vector` 时深度拷贝与移动语义的耗时差异。

**成功指标**
- 移动操作耗时应接近 0ms 且不随数据量增加而增长
- 通过 `static_assert` 在编译期验证类型的可移动性

**产出物**: `01_Linux_CPP_Foundations/w2_move_semantics/benchmark_move_vs_copy.cpp`

### W3：C++20 编译期约束与现代错误处理 ✅

**学习目的**  
利用 C++20 Concepts 实现编译期类型约束，使用 `std::expected` (C++23) 替代异常实现零开销错误处理。

**核心范围**
- **Concepts (C++20)**：`requires` 子句、自定义 Concept 定义
- **`std::expected` (C++23)**：零开销错误返回，替代 exception 和 `optional`
- `std::filesystem` 跨平台路径管理
- `std::string_view` 视图优化

**实战作业**  
编写 "AI 模型自动扫描器"：
- 使用 `concept Scannable` 约束输入类型
- 递归扫描 `/models` 目录，筛选 `.onnx` / `.engine` 文件
- 使用 `std::expected<Metadata, ScanError>` 返回结果或错误
- 解析逻辑强制使用 `string_view`

**成功指标**
- 核心解析代码无冗余的 `std::string` 临时对象产生
- 错误处理无 try-catch 依赖，全部基于返回值
- 传入不满足 Concept 的类型时，编译器给出清晰错误信息

**产出物**: `01_Linux_CPP_Foundations/w3_filesystem/model_scanner.cpp`

**学习目的**  
利用多核架构加速预处理。理解"预处理-推理-后处理"流水线的并行逻辑。

**核心范围**
- `std::thread` 生命周期管理
- `std::mutex` 与 `std::lock_guard`
- 条件变量 `std::condition_variable`

实现 "生产者-消费者" 图像处理原型：
- 线程 A 模拟图像采集入队

**成功指标**
- 系统在高并发下不出现死锁（Deadlock）

### W5：高性能并发进阶：通用线程池架构 (C++20) ✅

**学习目的**  
频繁创建/销毁线程开销巨大，线程池是多路视频流 AI 推理的工业标配。

**核心范围**
- **`std::jthread` (C++20)**：RAII 自动汇合，析构时自动 join
- **`std::stop_token` (C++20)**：标准化协同中断机制，替代 `std::atomic<bool>` 标志位
- **`std::condition_variable_any`**：配合 `stop_token` 实现异步唤醒
- **`alignas(64)` 缓存行对齐**：消除高并发下的伪共享 (False Sharing)
- 使用 `std::future` 和 `std::packaged_task` 实现异步结果获取
- **Concepts (`std::invocable`)**：编译期约束任务类型

**实战作业**  
手写支持泛型任务提交的 `ThreadPool` 类：
- 使用 `std::jthread` 管理工作线程
- 支持向池中提交任意 Lambda 函数
- 实现 `SubmitWithToken` 接口，任务可响应 `stop_token` 优雅中断
- 热点变量使用 `alignas(64)` + padding 独占缓存行

**成功指标**
- 成功并行执行 100 个模拟图像旋转任务
- 线程池在任务空闲时处于低功耗挂起状态（CPU 占用趋近 0%）
- `Shutdown()` 后，长任务能通过 `stop_token` 在 100ms 内响应中断

**产出物**: `01_Linux_CPP_Foundations/w5_thread_pool/thread_pool.hpp`

## 第二阶段：Linux 系统工程与高性能构建 (W6-W8)

### W6：Linux 高性能 I/O：文件映射 mmap 与 std::span ✅

**学习目的**  
加载数 GB 模型权重时，`mmap` 是零拷贝加载、提升启动速度的关键。

**核心范围**
- `mmap` 原理与系统调用
- 系统调用 `open`/`read` 与标准库缓冲对比
- **`std::span` (C++20)**：封装 `mmap` 返回的内存区域，实现类型安全的零拷贝视图
- 内存页对齐基础
- 虚拟内存与物理内存映射

**实战作业**  
对比实验：编写程序读取 500MB 权重文件：
- 记录使用 `fstream` 的加载耗时
- 记录使用 `mmap` 的加载耗时
- 将 `mmap` 返回的 `void*` 封装为 `std::span<float>` 或 `std::span<std::byte>`
- 验证通过 `span` 访问与直接指针访问性能一致

**成功指标**
- `mmap` 版加载速度明显优于传统 I/O
- 能使用 `std::span` 提供边界安全的零拷贝视图
- 能解释内存映射在进程间通信（IPC）中的潜在应用

**产出物**: `01_Linux_CPP_Foundations/w6_mmap_loader/mmap_benchmark.cpp`

### W13: 阶段性项目

**项目名称**: 高性能多线程图像预处理引擎 (C++20)

**任务描述**  
综合 Q1 所有知识，实现一个基于现代 C++ 线程池的图像处理系统。

**核心要求**
1. 使用 CMake 构建（C++20 标准），集成 GTest
2. 线程池基于 `std::jthread` + `stop_token`，支持优雅关闭
3. 使用 `std::span` 封装内存缓冲区，`std::mdspan` 表达图像布局
4. 核心算子（Resize/Gray）采用 W9-W10 中手写的优化版本
5. 输出详尽的各模块耗时报告（为 Q2 数据分析预热）

**系统架构**

```
Input Stream ──► Decode ──► [ThreadPool<jthread>] ──► Processing Pipeline ──► Output
                                     │
                       ┌─────────────┼─────────────┐
                       ▼             ▼             ▼
                   Worker 0      Worker 1      Worker N
                       │             │             │
                       └─────────────┴─────────────┘
                                     │
                       ┌─────────────┴─────────────┐
                       ▼             ▼             ▼
                   BGR2Gray      Resize      Letterbox
                       │             │             │
                 (std::mdspan) (std::mdspan)  (std::span)
```

**成功指标**  
产出一套基于 C++20/23 的可复用部署框架原型，作为 2026 简历的首个硬核项目。
