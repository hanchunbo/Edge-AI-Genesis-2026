## 第一阶段：端侧 LLM 推理工程 (W40-W43)

### W40 🔴 llama.cpp 源码精读与部署

**学习目的**  
2026 年端侧大模型落地已是主流方向。llama.cpp 是最具代表性的纯 CPU/GPU 推理实现，
其代码质量和工程实践是理解 LLM 推理工程的最佳入口。

**核心范围**
- llama.cpp 整体架构：`ggml` 张量库 + 模型加载 + 采样器
- GGUF 格式解析：模型量化存储（Q4_K_M, Q8_0 等 GGUF 量化类型）
- KV Cache 机制：为何 LLM 推理不能用 batch inference 的通常做法
- CPU SIMD 优化：llama.cpp 的 AVX2/NEON 矩阵乘法内核

**实战作业**  
在本地 RTX 3060 + 笔记本 CPU 上部署 Qwen2-1.5B：
- 对比 CPU (Q4_K_M) / CUDA (FP16) 的 Tokens/s 和首 Token 延迟（TTFT）
- 阅读 `llama_decode` 核心推理路径，在关键函数加注释
- 实现一个简单的命令行 Chat 封装（C++ 调用 `llama.h` API）

**成功指标**
- CPU Q4_K_M 推理 Tokens/s > 15（笔记本 i5-12500H 参考值）
- CUDA FP16 推理 Tokens/s > 60（RTX 3060 参考值）
- 能用自己的话解释 KV Cache 为什么能避免重复计算 Attention

**产出物**:
- `04_System_Integration/w40_llama_cpp/chat_demo.cpp`
- `docs/benchmarks/w40_llm_inference.md`

### W41 🟡 MLC-LLM 与编译期优化

**学习目的**  
MLC-LLM 代表了"模型编译"路线：用 Apache TVM 将模型编译为目标平台原生代码，
在 Android / iOS / WebGPU 上达到最优性能，是理解下一代部署技术的窗口。

**核心范围**
- TVM 计算图编译原理：Schedule, Tiling, Vectorization
- MLC-LLM Android 部署流程：`mlc_chat` APK 构建
- 与 llama.cpp 的路线对比：运行时解释 vs 编译期优化
- Quantization in TVM：`q4f16_1` 格式解析

**实战作业**  
在 Android 手机上运行 Qwen2-0.5B（via MLC-LLM APK）：
- 记录在手机 GPU（Adreno/Mali）上的 Tokens/s
- 与 W40 的 llama.cpp 数据对比，分析移动端 vs PC 端的推理差异
- 撰写《llama.cpp vs MLC-LLM 选型指南》

**成功指标**
- Android 手机上成功运行并对话（Tokens/s > 8）
- 选型指南有实测数据支撑，不止引用官方 benchmark

### W42 🔴 LLM 推理服务化——流式输出与并发

**学习目的**  
把 LLM 推理能力包装为服务，是 AI 应用工程的核心环节。
流式输出（SSE/WebSocket）和并发管理是与 CNN 推理完全不同的挑战。

**核心范围**
- 流式 Token 输出：Server-Sent Events (SSE) 实现
- 并发策略：Continuous Batching vs 多进程独占
- Context 长度管理：KV Cache 超限时的截断策略
- OpenAI-compatible API（`/v1/chat/completions`）接口规范

**实战作业**  
基于 llama.cpp 构建一个 OpenAI-compatible REST 服务：
- 实现 `/v1/chat/completions` 接口（含流式 `stream=true` 模式）
- 支持 2 路并发请求（Continuous Batching 或轮询调度）
- 用 Python `openai` SDK 客户端验证兼容性

**成功指标**
- 流式输出首 Token 延迟 < 500ms（本地 RTX 3060）
- 2 路并发时单路 Tokens/s 降幅 < 30%（调度合理）
- 与 `openai` SDK 兼容，可直接替换 API Key

**产出物**:
- `04_System_Integration/w42_llm_service/llm_server.cpp`

## 第二阶段：高级性能工程 (W44-W46)

### W44 🟡 FlashAttention 原理与 Kernel 分析

**学习目的**  
FlashAttention 是 2022-2026 年 Transformer 推理最重要的工程突破。
理解其 IO-aware 设计思路，是从"会用工具"到"能做优化"的分水岭。

**核心范围**
- Attention 计算的内存瓶颈分析（标准实现 vs FlashAttention 的 HBM 访问次数对比）
- Tiling 策略：将 QK^T 分块，避免 N×N 中间矩阵物化到 HBM
- FlashAttention-2/3 的改进：并行策略、Warp 级通信
- 用 `nsight-compute` 分析 FlashAttention Kernel 的内存带宽效率

**实战作业**  
对比标准 Attention 与 FlashAttention 的性能：
- 用 PyTorch 手写标准 Attention（展示内存墙问题）
- 调用 `flash_attn` 库，测量 seq_len=512/2048/8192 下的加速比和显存节省
- 绘制 Roofline 图，标注标准 Attention vs FlashAttention 的工作点

**成功指标**
- 能从数学推导出"标准 Attention 的 HBM 读写次数"
- FlashAttention 在 seq_len=2048 时显存占用 < 标准实现的 25%
- Roofline 图清晰展示两者的工作点差异

**产出物**:
- `04_System_Integration/w44_flash_attention/attention_benchmark.py`
- `docs/benchmarks/w44_attention_analysis.md`

### W45 🟢 CUDA Kernel Fusion 工程实践

**学习目的**  
Kernel Fusion 是减少 GPU 显存带宽消耗的核心技术：
把多个小 Kernel 合并为一个大 Kernel，减少中间结果写回 HBM 的次数。

**核心范围**
- Fusion 时机分析：Elementwise Fusion, Reduction Fusion
- `torch.compile` / `triton` 语言 vs 手写 CUDA 的 Fusion 对比
- CUTLASS 库入门：高性能 GEMM 的模板化实现
- 内存池（Memory Pool）设计：`cudaMallocAsync` + 自定义分配器

**实战作业**  
实现一个 Fused LayerNorm + GELU Kernel：
- 标准实现：两个独立 Kernel（LayerNorm → 写 HBM → GELU → 写 HBM）
- Fused 实现：一个 Kernel 完成，中间结果仅存 Shared Memory / Register
- 用 `nsight-compute` 对比 HBM 带宽利用率，量化 Fusion 收益

**成功指标**
- Fused Kernel 执行时间 < 独立 Kernel 总和的 70%
- `nsight-compute` 显示 HBM 带宽减少 > 40%

**产出物**:
- `04_System_Integration/w45_kernel_fusion/fused_layernorm_gelu.cu`
- `docs/benchmarks/w45_fusion_analysis.md`

## W50-W52：全年综合项目

### 🟢 项目名称：**EdgeMind — 端侧多模态 AI 助手**

**任务描述**  
综合 Q1-Q4 全年技术，交付一个集成视觉 + 语言能力的端侧 AI 助手。
这是 2026 年简历的最终 Boss 项目。

**核心功能**
1. **视觉理解**：摄像头输入 → YOLO 检测 → 场景描述（调用本地 LLM）
2. **语音交互**（选做）：Whisper ASR → LLM 推理 → TTS 语音输出
3. **多模型调度**：视觉模型（TRT）+ LLM（llama.cpp）的资源协调
4. **边缘优先**：目标在笔记本本地运行，不依赖云 API

**技术架构**

```
输入层：摄像头 / 麦克风
    ↓
感知层：YOLOv8n (TRT INT8) — 目标检测
    ↓
理解层：场景描述 Prompt 构建
    ↓
推理层：Qwen2-1.5B (llama.cpp CUDA) — 语义理解与回复生成
    ↓
输出层：Qt6 GUI / 终端 / gRPC
```

**考核标准**
- 视觉 → LLM 全链路端到端延迟 < 3s（RTX 3060）
- 连续运行 1 小时无 OOM（多模型显存管理）
- GitHub README 含完整演示视频

**产出物**: `04_System_Integration/edgemind/`
