# Claude Code 使用笔记

> 本文档整合了实战踩坑经验与系统学习笔记，既可快速速查日常操作，也可作为进阶功能参考。

---

## 一、基础操作速查

### 三种模式（Shift+Tab 切换）

| 模式 | 适用场景 |
|------|----------|
| **Ask**（默认） | 每次操作前询问确认 → 新任务、不确定时用 |
| **Auto** | 自动执行，不询问 → 信任 Claude 时用 |
| **Plan** | 只讨论方案，不动代码 → 架构设计、跨文件改动先用这个 |

### 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Shift+Tab` | 切换三种模式 |
| `Ctrl+G` | 在 VS Code 中编辑长提示词 |
| `Ctrl+B` | 当前任务转入后台（如 npm run dev） |
| `Ctrl+V` | 粘贴图片（UI 截图 → 代码） |
| `ESC×2` | 版本回滚（Rewind） |

### 常用命令

| 命令 | 功能 |
|------|------|
| `/plan` | 进入规划模式 |
| `/compact` | 压缩上下文（对话过长时用） |
| `/clear` | 清空对话，从零开始 |
| `/commit` | 智能生成 commit message 并提交 |
| `!<命令>` | 直接执行终端命令（如 `!ls`） |

## 二、实战踩坑记录（本项目经验）

### Plan Mode 使用方式

- Plan 模式下 Claude **只读不写**，用于前期探索和方案确认
- 确认方案后退出 Plan 模式，Claude 才会动代码
- 适合：新模块开发、涉及多文件的改动、不确定怎么做时先规划

### Token / 上下文管理

- 对话越长，Claude 越容易"遗忘"早期信息（Context Rot）
- 经验阈值：对话明显变慢或回答开始偏离时，开新会话
- 开新会话不丢失项目上下文：Claude 会自动读取 CLAUDE.md + MEMORY.md 恢复状态
- 手动压缩：`/compact` 让 Claude 把历史摘要化，节省 token 但保留对话

### 记忆系统（本项目已配置）

- `CLAUDE.md`（根目录）：项目级规则，每次对话自动加载，保持精炼（当前 ~130 行）
- `MEMORY.md`（自动维护）：Claude 跨会话的记忆文件，路径在 `.claude/projects/.../memory/`
- 让 Claude 记住某事：直接说"记住：xxx"
- 让 Claude 忘记/修正：直接说"删掉/更新关于 xxx 的记忆"

## 三、高级功能（按优先级排序）

### 3.1 Hooks（自动化钩子）★★ 建议学

在特定事件时自动触发脚本，配置在 `~/.claude/settings.json`：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx prettier --write \"$CLAUDE_FILE_PATH\""
      }
    ]
  }
}
```

支持时机：
- `PreToolUse`：工具调用前（可用于拦截危险命令）
- `PostToolUse`：工具调用后（可用于自动格式化）
- `Notification`：Claude 发送通知时
- `Stop`：对话结束时

典型用途：写完代码自动格式化、阻止危险命令（如 `rm -rf`）

### 3.2 Skills（自定义技能）★★ 按需学

预写好的 Prompt 模板，存为 `.claude/skills/<名称>.md`，用 `/<技能名>` 触发。
用于固化重复操作（如：符合本项目规范的代码审查、自动生成 notes.md 模板）。

与 CLAUDE.md 的区别：
- `CLAUDE.md` = 始终生效的项目规范
- Skills = 需要时手动触发的操作模板

### 3.3 SubAgents（子代理）★★★ 按需学

Claude 派出的"分身"，拥有独立上下文。适合：
- 大规模代码审查（读取大量文件，中间输出不污染主对话）
- 跨文件重构分析
- 批量生成测试/文档

主对话只收到最终报告，上下文保持干净。

**触发方式**：用自然语言请求，Claude 自动决定是否启动 SubAgent：
```
# 隐式并行（Claude 自行决定）
请同时实现这两个独立任务：1. xxx  2. yyy

# 显式并行
请用两个并行 SubAgent 分别实现：SubAgent A 做 xxx，SubAgent B 做 yyy

# 带 Worktree 隔离（各自在独立 git 分支，互不干扰）
请用 worktree 隔离，并行实现任务 A（分支 feature/xxx）和任务 B（分支 feature/yyy）
```

**实战踩坑（2026-03 W7 任务）**：

SubAgent 在后台运行时，**无法获得用户的工具确认**。Ask 模式下，所有工具调用都需要用户点击确认，而后台 Agent 没有界面弹窗，导致 Write/Bash/Edit 工具全部被权限拦截，Agent 无法完成任何代码修改。

**解决方案**：
- **切换到 Auto 模式**（Shift+Tab）再启动 SubAgent → Agent 可自动执行，不受拦截
- **直接在主对话实现** → 效果一样，只是没有真正"并行"，适合不想切模式时
- **不适合场景**：需要频繁 git 操作、文件写入的任务，Ask 模式下必须切到 Auto

### 3.4 MCP（外部工具接入）★★ 按需接

让 Claude 连接外部数据源的标准协议。
例：接入 Figma MCP 后，Claude 能精确读取组件参数而非"猜"截图。
未来可探索：数据库直连、浏览器控制等。

## 四、六境界成长路线（参考）

| 境界 | 关键词 | 核心动作 |
|------|--------|----------|
| 1 提示词工程师 | 单向指令 | 精准定义目标，拒绝平庸输出 |
| 2 规划者 | Plan Mode | 执行前先规划，让 Claude 找漏洞 |
| 3 上下文工程师 | Token 管理 | 主动 /clear，监控 Context 使用率 |
| 4 工具探索者 | MCP | 按需接入外部工具，理解架构 |
| 5 技能创造者 | Skills/Hooks | 将规范固化为自动化技能 |
| 6 编排者 | SubAgents | 管理多 AI 实例并行工作 |

**当前定位**：境界 2-3 之间（Plan Mode + 上下文管理已在用）。

**Git Worktrees**（境界 6 工具）：为不同 AI 分配独立分支，消除并行修改冲突，值得提前了解。
