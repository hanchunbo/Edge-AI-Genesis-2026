## 第一阶段：ONNX Runtime 推理引擎集成 (W14-W17)

### W14：ONNX Runtime C++ 基础与环境搭建
**学习目的**  
摆脱 Python `import onnxruntime` 的舒适区，学会在 C++ 环境下管理 Session、Environment 和 MemoryInfo。

**核心范围**
*   ONNX Runtime (ORT) C++ API 架构
*   `Ort::Env`, `Ort::Session`, `Ort::Value` 生命周期管理
*   模型输入输出节点动态查询
*   **Zero-Copy Input**: 结合 Q1 的 `mmap` 和 `std::span`，实现输入 Tensor 零拷贝

**实战作业**
*   加载一个 ResNet50/MobileNet 模型
*   封装 `Engine` 类，实现 RAII 风格的资源管理
*   **关键挑战**: 实现输入数据的 Zero-Copy (直接使用预处理好的 buffer 创建 Ort::Value，不发生 memcpy)

### W15：高效的前处理与后处理流水线
**学习目的**  
推理耗时往往只占 30%，70% 在前后处理。将 Q1 手写的 `Resize/CenterCrop` 接入流水线。

**核心范围**
*   NHWC 到 NCHW 的内存布局转换 (HWC -> CHW)
*   Image Normalization (Mean/Std) 的 SIMD 优化实现
*   后处理解码 (如 Classification Top-K, Detection NMS) 的 C++ 实现
*   避免使用 `cv::dnn::blobFromImage`，坚持手写以掌握底层

**实战作业**
*   构建完整的 `Preprocess -> Run -> Postprocess` 链路
*   对比 "OpenCV 纯 CPU 实现" 与 "Naive C++ 实现" 的耗时

### W16：复杂模型支持：动态 Batch 与 多输入输出
**学习目的**  
处理真实业务场景中的不定长输入（如 OCR 文字识别）和多头输出（如目标检测）。

**核心范围**
*   Dynamic Shape 支持配置
*   多线程 Session (`InterOpNumThreads` vs `IntraOpNumThreads`) 调优
*   I/O Binding：将输出 Tensor 直接绑定到预分配内存，减少设备到主机的拷贝

**实战作业**
*   部署一个 YOLOv8/v10 模型 (多输出头)
*   实现高效的 C++ NMS (非极大值抑制)
*   压力测试：在不同 Batch Size 下的 Latency 和 Throughput 曲线

### W17：第一阶段复盘与代码重构
**核心任务**
*   将 ORT 封装库合入 `02_Inference_Analysis/lib/inference_engine`
*   使用 Google Test 覆盖核心推理接口
*   **MEM 视角**: 撰写《推理引擎选型分析报告》，对比 ONNX Runtime, TensorRT, OpenVINO 适用场景

## 第二阶段：数据驱动性能分析与量化 (W18-W21)

> **特别说明**: 结合你 3 年数据分析背景，本阶段是你的**高光时刻**。

### W18：性能剖析与瓶颈定位 (Profiling)
**学习目的**  
不盲目优化。数据分析师相信数据。使用专业工具定位是 CPU 算力受限还是内存带宽受限。

**核心范围**
*   **Nsight Systems** 全局性能分析 track
*   CPU Flame Graph (火焰图) 采集
*   **Roofline Model** (屋顶线模型) 理论：计算密集 vs 访存密集
*   Memory Bandwidth Usage 分析

**实战作业**
*   对 W16 的 YOLO 推理程序进行 Profiling
*   生成 Timeline 视图，精准指出 Pre-processing, Inference, Post-processing 各占用的微秒数
*   **产出**: 一份详细的性能诊断报告 (PDF/Markdown)

### W19：量化理论 (Quantization Theory)
**学习目的**  
理解 FP32 -> Int8 带来的精度与速度权衡。

**核心范围**
*   对称量化 vs 非对称量化
*   Calibration (校准): Min-Max, Entropy (KL 散度), Percentile
*   量化误差分析 (MSE)
*   **Per-Channel** vs **Per-Tensor** 量化

**实战作业**
*   (Python 脚本) 手写一个简单的 Quantizer，对一组权重进行伪量化
*   计算并可视化量化前后权重分布的 Histogram (直方图)，分析精度损失原因

### W20：ONNX Runtime Int8 量化实战
**学习目的**  
在生产环境中落地 PTQ (Post-Training Quantization)。

**核心范围**
*   ORT Quantization Tool 使用
*   校准数据集准备策略
*   精度恢复技巧 (QAT 简介)
*   **混合精度 (Mixed Precision)**: 敏感层保持 FP16/FP32，其余 Int8

**实战作业**
*   将 YOLO 模型量化为 Int8
*   在 C++ 引擎中加载 Int8 模型
*   **关键指标**: 模型体积减小 50%+，推理速度提升 1.5x+，mAP 掉点控制在 1% 以内

### W21：阶段性数据分析报告
**核心任务**
*   发挥数据分析优势，构建**自动化性能报表系统**。
*   脚本自动运行 Benchmark，生成：
    *   Latency vs BatchSize 曲线
    *   Accuracy vs Quantization Mode 散点图
    *   Memory Footprint 热力图

## W26：年中项目 (Mid-Year Capstone)

### 项目名称：**EdgeSight - 智能安防实时分析终端**

**任务描述**
开发一个具备完整 GUI 的 AI 视频分析软件，集成 YOLO 目标检测能力。

**核心功能列表**
1.  **多源输入**: 支持本地视频文件、USB 摄像头、RTSP 网络流。
2.  **高性能推理**:
    *   内置 ONNX Runtime 推理引擎 (W14-W17 成果)。
    *   支持 FP32 / Int8 模型热切换 (W20 成果)。
    *   C++20 线程池调度 (Q1 成果)。
3.  **可视化分析**:
    *   实时绘制检测框、类别、置信度。
    *   **实时仪表盘**: 显示当前 FPS、推理延迟、物体计数曲线 (W18/W21 经验)。
4.  **工程化交付**:
    *   提供 Windows/Linux 双平台安装包。
    *   内存占用不超过 500MB (W1/W6 经验)。

**考核标准**
*   **稳定性**: 能够连续运行 24 小时无 Crash (内存泄漏检测过关)。
*   **性能**: 在 RTX 3060 上单流推理达到 60 FPS+，界面无卡顿。
*   **代码质量**: 核心模块单元测试覆盖率 > 80%，符合 Google Style。
